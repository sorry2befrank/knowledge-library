# Sweep-log and trust-state protection reference

Reference only. No real sweep log, trust-state row, UNDERSTUDY report, citation, prompt or private identity is exported. Formats come from the sources named in provenance and the documented legacy observations. Local counts-only checks may read protection evidence, but no real row, name, path or protected target belongs in this pack. The new pure adapter is `vendor/sweep-protection.mjs`; its implementation is pinned by the pack artifact inventory, without a self-hash. Synthetic cases are in `fixtures/reference/sweep-protection.cases.json`.

This reference implements the fail-closed input-format portion of DESIGN.md's "The kernel: eligibility set E" hard-pin requirement. The final text currently places sweep-cited protection under rule 2; earlier review text called it rule 8. Follow the named hard-pin requirement, not that historical number. This adapter is not the whole kernel, a filesystem reader, an authorization gate, a citation verifier or a complete S2 conformance result.

### Accepted legacy non-report records

All records still require a valid wrapper minute timestamp and the normal `- <timestamp> - ` prefix. In addition to the current producer forms, the adapter recognizes these exact, anchored message forms:

| Form (fictional placeholders only) | Provenance |
|---|---|
| `claude returned nothing - watermark NOT advanced` | `understudy-trust-ledger:49` names this historical non-report category. The exact message is an observed append-only-log form; no current producer examined emits it. |
| `swept <N> files - <N> finding(s) -> _UNDERSTUDY/proposals/<stamp>.md` | Observed in the append-only log; no current source examined emits it. Counts are decimal integers; stamp is one filename component ending in .md. |
| `<project>: RUN FAILED (<reason>, no report produced) - see _UNDERSTUDY/failed/<file>` | Observed in the append-only log; no current source examined emits it. The failed filename is one nonempty component without a slash or backslash; Unicode, spaces and punctuation do not make it a different log category. This form carries no accepted or rejected report. |

These are compatibility observations, not a source script to execute or a permission to ignore other unknown rows. Missing fields, unsupported paths or misspelled statuses fail closed. The grammars are anchored: an additional suffix fails unless it is valid literal content within the final filename component. That filename is not opened or trusted by this adapter. The counts-only local receipt records recognition totals without copying any historical row or its values.

The source trust script's missing/corrupt-file fallback restores a default counting ledger. This adapter intentionally does **not** inherit that behavior. Missing, unreadable, undecodable or malformed protection evidence yields `adjudication-unknown` and blocks every candidate in the folder. The source counting baseline is not proof that an individual report was adjudicated; this adapter does not use it to waive pending protection.

## Adapter behavior

`parseSweepProtection` takes caller-provided `sweepLogText`, `trustLedgerText`, `understudyText`, exact `project` identity and `cutoffTimestamp` in the producer's `YYYY-MM-DD HH:mm` local-clock format. Missing/unreadable mandatory inputs are represented by null. An absent UNDERSTUDY.md may be null only when the caller established it is absent, not merely unreadable.

The adapter validates timestamps and adjudication shapes. It rejects duplicate JSON members recursively, comparing decoded keys so escaped spellings cannot hide a duplicate. It never fills missing ledger entries. A calendar-valid date-only adjudication key is well-formed legacy state, but it matches no minute-keyed report: the intended report stays pending and its citations remain protected. Every other malformed key fails the whole ledger. Every nonempty log line must be a valid report row, a current producer non-report form, or one of the three legacy forms listed above. Unsupported annotations, lowercase statuses, malformed dates and unknown record forms are unknown evidence, not non-events. CRLF, CR and LF delimit lines; decoding replacements and NULs remain errors. Report labels match the supplied identity exactly. A nonexact label with the same lowercase or uppercase spelling yields project-label-case-variant, including REJECTED rows: these can name the same Windows folder and cannot silently disappear. This rejection does not normalize identities or infer aliases; filesystem identity remains a caller obligation.

Every pending ACCEPTED report and every report at or newer than the fourteen-day cutoff is protective, including clean, false, neutral or learned recent adjudications. Cutoff comparison is inclusive. The digit-boundary header date matcher recognizes ISO timestamps, including T separators and offsets. Headers use the supported first-level scan framing with either a date/timestamp alone or the exact supplied project label followed by that stamp; arbitrary middle text is unsupported. Calendar, clock and numeric offset fields must be in their accepted ranges. Header dates must not decrease in file order; accepted-event days must not decrease in log order. These are consistency checks only. Model-written dates, offsets, header counts and separators do not authenticate report identity or completeness. The adapter never converts a header timezone to choose a report.

Every ACCEPTED event must be represented in the consistency checks, including older adjudicated events. Each day needs exactly as many blocks as events. More blocks yields same-day-block-ambiguity; fewer yields same-day-report-ambiguity. A wholly missing single-event day yields required-report-block-unmatched; a missing multi-event day yields same-day-report-ambiguity. The former exception for a missing single older adjudicated block is removed. Repeated exact report identities fail closed.

Whenever any event is protective, its pin set is the union of citations from **all represented blocks**, including older/adjudicated blocks and blocks containing a no-findings phrase plus citations. A model-written day cannot move a citation into an unprotected report. Date, order or count inconsistencies remain unknown. Matching counts still prove no authenticated association: counterfeit headers can rebalance them. Known is format coverage only, and the caller must independently establish complete trustworthy append evidence before relying on this superset.

Unmatched events, orphan blocks, missing headers, empty blocks or malformed target-bearing citation lines block every candidate. An absent UNDERSTUDY.md blocks when any accepted event exists. Every block needs the source wrapper's complete --- delimiter. Nonblank content after it and before the next supported header yields report-content-after-terminator. Unsupported first-level headings inside a block are unknown. A rejection-only heading view treats Python-only whitespace as spacing and removes format characters, so obfuscated Understudy headings are refused; that view never changes citation targets.

Before the first supported report header, only blanks, --- and the generic # UNDERSTUDY.md marker are tolerated. Citation-shaped lines there yield citation-outside-report-block; other substantive preamble yields report-preamble-unrecognized. The wrapper's longer prose preamble is therefore not claimed as supported input. A caller may supply a report-only view only after independently validating the excluded wrapper bytes and proving it discarded no report evidence; otherwise it supplies unknown. An unrecognized fragment is never silently ignored.

Citation matching includes the five Python-only whitespace characters U+001C through U+001F and U+0085 wherever the source grammar uses whitespace. The lexical class sits outside target captures. Unsupported Markdown links, inline backticked paths, backticked targets followed by citation delimiters, and detected plain path/line references are conservatively unknown. Prose mentions, filenames and wikilinks are best-effort detections here, not an exhaustive reference inventory. The kernel's explicit-reference rule must independently cover those mentions across UNDERSTUDY.md, including Unicode, quoted paths and wikilinks.

A zero-citation block is accepted with an empty pin set only when its sole content line is the verifier's no-findings phrase: Nothing worth your attention, or Nothing new worth your attention (case-insensitive, source whitespace grammar, optional final period; `understudy-verify-report:245–248`). Only exact ## Findings or ## Verdict section headings and the complete separator are excluded from this test. Every other heading counts as content; finding prose cannot hide in a heading. Added prose or other zero-citation text remains required-report-citations-missing when a protective event exists. This exception covers the bare quiet form, not template metadata such as Read or Could not verify. It records explicit quiet evidence, not an inference that missing evidence is harmless.

Citation targets are collected with only their terminal numeric line suffix removed. Target whitespace, case, format characters and Unicode spelling are preserved exactly: the source resolver does not trim target identity (`understudy-verify-report:92–101`). Unsupported suffixes such as ranges, URI schemes or alternate-stream syntax yield unknown; an optional drive prefix is not a line suffix. These are unresolved references, not approved reads. With no protective events, this age/pending rule contributes no pins; other kernel rules still apply. REJECTED events do not represent appended UNDERSTUDY.md blocks. A folder with an UNDERSTUDY.md but no report lines for its exact identity remains unknown.

The output is either `known` with `protectedTargets` and `protectedReports`, or `adjudication-unknown` with `blockEveryCandidate: true`. An unknown result must never be interpreted as an empty pin set. Conservative syntax/shape failures can reduce yield; they do not grant eligibility.

## Caller obligations and limits

The local implementation must read all evidence strictly and coherently, distinguish absence from access/decoding errors, detect changes during reads, bind reads to the canonical folder identity/volume and independently establish trustworthy complete append evidence. Header and separator counts cannot establish that evidence. Unverified append completeness or framing yields adjudication-unknown at the caller before relying on the parser's union. The source label must map uniquely to the folder: case-only Windows aliases, other collisions or uncertain mappings yield adjudication-unknown. Exact spelling does not prove folder identity. The source sweep log is hub-wide, not an automatically present per-folder file. Locations and identity mappings are local configuration; this pack exports no workstation paths or private mappings.

The caller computes now minus fourteen days with a trusted clock/timezone and floors the local-wall cutoff to the minute. It never substitutes UTC or a caller-selected future time. For an ambiguous repeated clock hour, it chooses a cutoff before the entire repeated interval or returns unknown. The parser has no clock or timezone authority; accepting timestamp syntax cannot prove those conditions.

Callers resolve returned citation targets under the approved local reference model, including ambiguity and missing/unreadable-target protection, without following unapproved paths or reparses. They must cover instruction/dependency references and any unsupported citation syntax conservatively. No private target, source text or detailed state row may be sent to the cloud; publish only approved rule/reason identifiers and aggregates. A freshness or coverage failure blocks eligibility independently of format parsing.

The parser covers only the formats listed here. It does not prove that source adjudications are authenticated, reports are true, a pending report is harmless, all reference forms are covered, or the S2 kernel is conformant. Integration tests must bind this adapter to those IO/identity/freshness protections and the kernel's unknown-evidence gate before real focus operation. S2 measures its unknown rate on real data with counts only before the hard-pin rule relies on it. A known result grants no removal authority. The cloud lane does not execute the original trust script, modify its state, call the sweep/adjudicator or access their live files.

Measured readiness at the prior Round3 revision: **0 of 25 real folders returned known**, and every unknown folder blocked removal. First reasons were citation-unparseable in 17 folders, header ambiguity in 4, and no matching report lines in 4. This remains a North Star/yield blocker, not a successful weekly cleanup result. Round4's stricter parser has been tested on synthetic inputs; these historical counts are not a new measurement of this revision. S2 must repeat the counts-only census before operational use and improve format coverage without weakening protection.

The adapter is newly authored for the Library from sanitized format declarations. Provenance retains source hashes/symbols/transforms; the pack is published under the repository's MIT license. No runtime protection evidence is copied into this pack.
