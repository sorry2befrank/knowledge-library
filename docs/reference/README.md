# Knowledge Library reference pack

Pack format: `reference-pack/1`. This is the sanitized reference material for the cloud build. It contains source-derived declarations, schema mappings, compatibility notes and synthetic examples. It contains no knowledge corpus or production state.

This is the reviewed reference pack that the repository README (rule 2) allows. It holds sanitized extracts of formats, rules and one small pure function from brain-mcp, Orrery and Understudy, a newly authored pure protection-format adapter, and synthetic fixtures that cloud-lane tests may load and run. It is not the specification, not an installed or accepted policy (the signed policy loader must not accept policy/deny.template.json as a bundle), not the library-evidence/v1 schema, and not real content. Nothing here asks you to run, install, contact or change anything, including Orrery, brain-mcp or Understudy. docs/DESIGN.md and your session work order govern: where this pack and DESIGN.md disagree, follow DESIGN.md and record the disagreement in your turnover. Decisions cited as D1-D13 are listed in DESIGN.md §14.5. These four paths belong to the local lane; do not edit them, and request any change in your turnover.

## Boundaries for the cloud lane

1. Use generic source declarations and synthetic examples as references. Do not restore removed personal benchmarks, private project lists, operational prompts or workstation paths.
2. Keep the private matching overlay outside the repository. A hash of a private name is not a privacy boundary. Real-content admission needs approved source/classification configuration; this template is not that configuration.
3. Apply the reconciled refusal rules before durable writes. Legacy guard signals do not authorize quarantine storage of content the current policy refuses.
4. Perishability estimates the density of claims worth checking. It does not judge truth, relevance, sensitivity or removal eligibility.
5. Observations, restores, ghosts and ordinary agent feedback remain unconfirmed until the approved owner-confirmation mechanism supplies the required receipt.
6. Generic ladder outcomes do not grant Library removal, promotion or recovery authority. Registry capability fields described here are adaptations that the local lane must implement before registration.
7. The Library repository owns the canonical machine-readable `library-evidence/v1` schema and producer. This pack documents the adopted prose and expected semantics; it does not invent a competing JSON schema. The schema and shared fixtures are published at the S1c merge recorded below. The dormant Orrery consumer remains future work and must use those pinned canonical bytes.
8. Source-derived fixtures describe legacy compatibility where labelled. Adopted Library expectations are labelled separately. Do not silently turn legacy behaviors into new authorization rules.
9. The protection-format parser covers the formats listed in `sweep-protection.md`. It is not S2's kernel or its IO and identity checks. An unknown result blocks every candidate; a known result grants no removal authority. S2 measures the unknown rate on real data (counts only) before rule 2 relies on it.
10. No verified ripple canary measurement is present. The default-off Orrery counter remains required future work; the ripple term stays at 1 until the approved canary supplies pinned evidence. This pack runs no canary and installs no counter.
